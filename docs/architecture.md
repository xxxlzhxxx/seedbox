# SeedBox 架构设计

SeedBox 是一个用来搭建可交互世界、让玩家和 Agent 控制角色在其中行动的开源项目。以下是拟议架构。现有广场示例已经展示地点之间的命令行寻路，下一步用浏览器里的 3D 场景验证从素材到交互的完整流程。

## 七个模块

| 模块 | 职责 | 示例 |
| --- | --- | --- |
| 1. 数据采集 | 导入照片、视频、LiDAR 扫描、平面图、地图与参考图，记录素材来源、尺度和定位信息。支持素材不齐全时分批补充。 | 先从照片和地图搭广场外部，再用平面图补室内布局。 |
| 2. 建模器 | 环境建模管线生成地形、建筑、道具、纹理和高斯泼溅资产。角色建模管线生成角色网格、骨骼和动画。 | 用简化网格搭出楼梯，用实拍重建补外观，再导入可行走的骨骼角色。 |
| 3. 世界描述与资产规范 | 定义坐标系、单位、对象 ID、变换、资产引用、碰撞、交互点和语义标签，供建模器、编辑器和运行时读写。 | 门有稳定 ID、位置、碰撞体和可用动作。换门的模型后，场景规则仍可通过同一个 ID 找到它。 |
| 4. 世界编辑器 | 组装场景、校准尺度、替换资产、标注可步行区域与交互点，预览并导出。 | 调整广场台阶的位置，标记入口、门和座位。 |
| 5. 世界运行时 | 加载并渲染场景，处理碰撞、寻路、对象交互和共享状态。 | 验证角色是否能开门，更新门的状态并让其他角色看到。 |
| 6. 角色运行时 | 将键鼠、脚本或 Agent 的输入转成角色动作，管理角色的感知、移动和动画。 | 玩家接管角色，或由 Agent 指挥角色走到门口、开门并坐下。 |
| 7. 场景规则 | 定义任务、触发器、计分、结束条件和重置逻辑。 | 办公室场景判断角色是否坐到指定座位。多 Agent 对抗场景可定义回合和胜负。 |

## 模块边界

- **世界运行时维护事实，角色运行时执行意图，场景规则判断目标。** 玩家或 Agent 发出开门意图，角色运行时提交动作，世界运行时验证条件并更新门的状态，场景规则根据事件判断任务进度。
- **视觉、碰撞和交互可以独立更新。** 例如广场外观可采用高斯泼溅，用简化网格支持碰撞和步行，入口和店铺则作为带稳定 ID 的交互对象。素材不足时可以先搭通行和交互，再补视觉细节。
- **优先定义世界描述和交互接口。** 第一版复用 Blender、现有建模工具与渲染引擎，编辑器先覆盖组装、对齐和交互标注，场景规则先用脚本表达。七个模块是逻辑边界，首版可在主仓库推进新实现，并复用现有的场景与角色示例。

## 首个 3D 端到端 Demo

以大钟寺办公室入口为参考，搭建一个可公开演示的场景。路线从办公室入口经过门禁，到达访客座位。

1. 从照片和平面参考搭出入口、通道和座位区域，配置碰撞和可步行区域。
2. 在浏览器中用键鼠控制角色走到门禁、开门、进入室内并坐下。
3. 让 Agent 通过同一套观察和动作接口完成路线。运行时返回动作结果，场景规则在角色坐到指定座位时报告完成。
4. 替换门或座位的视觉资产，验证碰撞、交互和任务仍能运行。
